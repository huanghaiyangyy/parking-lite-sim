# 使用指南

本文是 **Parking-lite Demo** 的完整中文 walkthrough：安装、跑通 demo、车辆控制、修改相机 `K`/`D`、校验 AVM，以及常见问题排查。

技术术语（ModernGL、OpenCV fisheye、IPM、BEV、FLU、`K`/`D` 等）保留英文写法，便于对照代码与配置。

---

## 1. 环境要求

- **Python**：3.10+（项目在 3.13 下验证过）
- **OS**：Linux / macOS / Windows（Windows 请用对应的 venv 激活命令）
- **GPU**：不强制。ModernGL 使用 `standalone` 上下文；无 GPU 时可走软件渲染（常见为 **llvmpipe**），速度较慢但功能可用
- **依赖**：见仓库根目录 `requirements.txt`

---

## 2. 安装

```bash
git clone <YOUR_REPO_URL> parking-lite-demo
cd parking-lite-demo

# 建议使用虚拟环境，避免污染系统 Python
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

pip install --upgrade pip
pip install -r requirements.txt
```

依赖一览：

| 包 | 用途 |
|----|------|
| `moderngl` + `glcontext` | Offscreen OpenGL 渲染 |
| `numpy` | 数组 / 矩阵 |
| `pillow` | 读写 PNG / GIF、拼图 |
| `pyglm` | 视图 / 投影矩阵 |
| `pyyaml` | 加载 YAML 配置 |
| `opencv-python-headless` | `cv2.fisheye`、`cv2.remap`（无 GUI） |

确认安装：

```bash
python -c "import moderngl, numpy, PIL, glm, yaml, cv2; print('ok', cv2.__version__)"
```

## 4. 车辆控制示例

运动学控制器与渲染解耦：先算位姿，再 `apply_to_world` 或手动 `set_ego_pose`。

### 最小示例

```python
from scene.world import World
from vehicle import VehicleController

world = World.from_config("configs/default.yaml")
ctrl = VehicleController("configs/vehicle.yaml")

ctrl.reset(x=0.0, y=0.0, yaw=0.0, speed=0.0)
ctrl.set_controls(steer_wheel_deg=200.0, accel_mps2=1.0, gear="D")

for _ in range(100):
    state = ctrl.step()          # 默认 dt 来自 vehicle.yaml（0.02 s）
    ctrl.apply_to_world(world)   # 同步到渲染世界

images = world.render_cameras()
bev = world.stitch_avm(images)
```

### 状态字段速查

- `state.x`, `state.y`, `state.yaw` — 世界 FLU 位姿（米 / 弧度）
- `state.speed_mps` — 有符号纵向速度（D ≥ 0，R ≤ 0）
- `state.speed_signal_mps` — `abs(speed_mps)`
- `state.steer_wheel_deg` / `state.road_wheel_deg`
- `state.wheel_pulse_count` / `state.wheel_speed_mps` — 顺序 `fl, fr, rl, rr`

### 官方 demo

```bash
python scripts/run_vehicle_control_demo.py
```

会模拟约 8 秒：D 加速 → 转向 → 刹车 → 短时 R 倒车，并写出：

- `output/vehicle_control/trajectory.csv`
- `output/vehicle_control/trajectory.png`
- 若干 `god_view_t*.png`

### 调参

编辑 `configs/vehicle.yaml`，例如：

```yaml
vehicle:
  wheelbase_m: 2.7
  steering_ratio: 16.0
  max_steer_wheel_deg: 500
  max_road_wheel_deg: 35
  max_speed_mps: 5.0
  wheel_radius_m: 0.33
  pulse_ticks_per_wheel_rev: 96
control:
  dt_s: 0.02
```

改完后重新实例化 `VehicleController(...)` 即可，无需改 Python 代码。

## 5. 如何修改相机 K / D

所有环视相机内参在 **`configs/default.yaml`** 的 `cameras:` 段。

### 字段说明

| 字段 | 含义 |
|------|------|
| `translation_m` | 相机在车辆 FLU 下的平移 `[x, y, z]`（米） |
| `rotation_deg` | `[roll, pitch, yaw]`（度），固有 XYZ；pitch 朝向地面为负 |
| `K` | 3×3 内参矩阵（对应 `image.width` × `image.height`） |
| `D` | OpenCV fisheye 畸变 `[k1, k2, k3, k4]`（仿真 GT） |

### 示例：改前视畸变

```yaml
cameras:
  front:
    D: [-0.08, 0.03, -0.01, 0.002]   # 加强 / 调整畸变后保存
```

然后：

```bash
python scripts/run_phase2_fisheye.py   # 看单相机 + D 对比图
python scripts/run_phase3_avm.py       # 看 BEV 是否仍自洽
python scripts/run_demo.py --no-motion
```

Phase 2 会额外写出 `front_D_compare_zero_yaml_strong.png`，便于直观对比 `D=0` / YAML / 强畸变。

### 改分辨率时注意

若修改 `image.width` / `image.height`，请同步调整各相机 `K` 中的 `cx/cy`（通常约 `width/2`、`height/2`）以及 `fx/fy`，否则投影中心会偏。

### 渲染路径

- 默认 `render.fisheye_mode: opencv`（宽 pinhole → KB LUT → remap）
- 设为 `equidistant` 可走旧 GPU shader 路径（一般不推荐用于校验 K/D）

## 6. 如何校验 AVM

### 快速 smoke（随 demo）

`run_demo.py` 默认会写 `output/demo/validation_summary.txt`（可用 `--no-validate` 跳过）。

### 完整 Phase 4

```bash
python scripts/run_phase4_validate.py
```

检查内容概要：

1. **内参**：地面采样的 KB 投影 vs `cv2.fisheye.distortPoints`（像素误差）
2. **外参 / 地标**：过道 GT marker → BEV，与 CAD 对比平面误差（m / px）
3. **接缝连续性**：前后 × 左右 overlap 区域 luma MAD
4. **敏感度**：对同一组鱼眼图施加约 ±2° 外参噪声后重拼，paint-centroid / BEV MAD 应上升

产物：

- `output/phase4/bev_gt.png`、`bev_perturbed.png`、`compare.png`
- `*_overlay.png`
- `report.md` / `report.txt`（PASS / WARN / FAIL）

阈值阈值见 `avm/validate.py` 中的 `THRESHOLDS`（例如覆盖率 ≥ 0.55、GT marker 均值 ≤ 0.25 m 等）。

### 自洽性说明

本栈用 **同一套 YAML `K`/`D`/外参** 既做成像又做 IPM。GT 自洽时应通过；若你故意改坏外参，Phase 4 敏感度项应能检出。这里 **没有** 在线标定求解器，只做检测。

## 7. 坐标系速查

| 坐标系 | 轴向 | 用途 |
|--------|------|------|
| Vehicle / world **FLU** | +x 前，+y 左，+z 上 | 位姿、外参、BEV 范围 |
| OpenCV optical | +X 右，+Y 下，+Z 前 | 鱼眼 / IPM |
| GL scene | Y-up，+Z 前 | 网格几何 |

BEV 图像：上 = 车头前方，左 = 车辆左侧。

## 8. 故障排查

### 8.1 `ModuleNotFoundError: No module named '...'`

未激活 venv，或未安装依赖：

```bash
source .venv/bin/activate
pip install -r requirements.txt
which python   # 应指向 .../parking-lite-demo/.venv/bin/python
```

### 8.2 OpenGL / llvmpipe / 无显示环境

本项目使用 `moderngl.create_context(standalone=True)`，**不需要窗口**。无 GPU 时常见 renderer 为 **llvmpipe**（软件光栅化）：

- **现象**：能跑，但较慢；首帧 / 高分辨率更明显
- **处理**：属正常；服务器 / CI / 无桌面环境都可接受。启动日志中会打印 `GL_RENDERER` / `GL_VERSION`

若创建上下文失败：

- Linux：确认有可用的 GL 实现（如 Mesa）
- 容器：可能需要挂载或安装 `libgl1-mesa-dri` 等（视发行版而定）
- 仍失败时把完整 traceback 与 `GL_RENDERER` 日志一并保留

### 8.3 鱼眼图大片黑色

- 单宽 pinhole 无法覆盖 θ ≥ ~90° 或 frustum 外射线 → 采样为黑（已知限制）
- 检查 `render.pinhole_fov_y_deg`（默认 165）；过大接近 180° 时数值不稳定
- 确认相机 pitch 朝向地面，且 ego 位姿在车位附近（可用 `run_phase1_scene.py` 看 god view）

### 8.4 BEV 接缝明显 / 物体“拉丝”

- IPM 假设 **z=0 平坦地面**；柱子、车身、抬高 marker 会剪切，属预期
- 外参或 `K`/`D` 与成像不一致时接缝会变差 → 跑 Phase 4 看 report
- Feather 只能软化重叠，不能修正错误外参

### 8.5 `output/` 被 git 忽略

`.gitignore` 故意忽略 `output/`（生成物）。本地跑 demo 会创建该目录；克隆后仓库内可能没有历史输出，需自行生成。

### 8.6 venv 相关

```bash
# 重建干净环境
deactivate 2>/dev/null
rm -rf .venv
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

不要把 `.venv/` 提交进 git（已在 `.gitignore` 中）。

### 8.7 Windows 路径

激活：`.venv\Scripts\activate`。其余命令相同；若 PowerShell 限制脚本执行，可用：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

或直接：`.venv\Scripts\python.exe scripts\run_demo.py`。
